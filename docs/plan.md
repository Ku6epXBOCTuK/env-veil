# Env Veil — план реализации

## Статус

- Рабочее название: **Env Veil**.
- `Hide Env` не подходит: название уже использует расширение `chefrei.hide-env` для того же назначения.
- На момент проверки точных совпадений `Env Veil` в Visual Studio Marketplace и GitHub не найдено. display name в Marketplace не является глобально уникальным, поэтому перед публикацией нужна финальная проверка.
- Исходный `env-guard` используется только как референс поведения. Его код, оформление и графические ресурсы не копируются.
- План относится к новой реализации на TypeScript.

## 1. Продуктовые решения

Расширение:

- автоматически открывает `.env` и `.env.*` в защищённом custom editor;
- не изменяет `workbench.editorAssociations` автоматически;
- показывает ключи, комментарии, пустые строки и структуру файла;
- скрывает только непустые значения переменных;
- раскрывает и скрывает все значения одной кнопкой;
- автоматически скрывает значения по таймеру и при потере фокуса;
- предоставляет кнопку открытия файла во встроенном или внешнем редакторе;
- использует английский интерфейс;
- работает офлайн, без telemetry и сторонних запросов;
- ориентируется на современный desktop VS Code с базовой версией 1.105;
- не редактирует `.env` непосредственно в webview.

### 1.1. Пользовательский сценарий

1. Я открываю `.env` или `.env.*`, и Env Veil открывается автоматически.
2. Я вижу ключи, комментарии и структуру файла, но все непустые значения скрыты масками.
3. По кнопке `Reveal Values` я показываю все непустые значения одновременно; запускается таймер автоматического скрытия.
4. По истечении таймера или при потере фокуса непустые значения автоматически скрываются снова.
5. По кнопке `Open in Editor` файл открывается в выбранном мной редакторе: встроенном в VS Code или внешнем, например Sublime Text.
6. После сохранения и возвращения в Env Veil файл обновляется, а значения остаются скрытыми.

Сценарий не обещает защиту от человека, который уже имеет доступ к VS Code и исходному файлу. Задача расширения — предотвращать случайный визуальный показ значений во время screen sharing, записи и демонстрации.

### 1.2. Если пользователь заменил редактор

Если пользователь через `Set Default` или `workbench.editorAssociations` постоянно выбрал Text Editor или другой custom editor, Env Veil не открывается и не может маскировать значения. Расширение не должно молча создавать впечатление, что защита продолжает работать.

После активации расширение проверяет открытые `.env` в обычных Text Editor. Не чаще одного раза за окно VS Code показывается предупреждение:

- Env Veil не активен для этого файла;
- файл открыт другим редактором;
- значения не маскируются;
- как восстановить Env Veil через `Reopen Editor With…` → `Set Default` или удалить соответствующую association.

Предупреждение предлагает открыть текущий файл в Env Veil, но не изменяет editor associations автоматически. README содержит тот же текст и пошаговую инструкцию. Переустановка расширения не считается способом восстановления, потому что пользовательские настройки сохраняются.

## 2. Цели

1. В скрытом состоянии пользователь видит маски вместо значений.
2. Reveal и Hide управляют всеми значениями одновременно.
3. Кнопка открывает файл в редакторе, выбранном пользователем в настройках.
4. Расширение не создаёт лишние вкладки, не фокусирует редакторы и не закрывает их по таймерам.
5. Поведение предсказуемо при смене вкладки, фокуса, редактора и настроек.
6. Внешний редактор запускается без передачи пути файла через shell.
7. TypeScript использует строгую типизацию и не допускает явного `any`.
8. Сборка и тесты воспроизводимы из чистого клона.

## 3. Вне области MVP

- редактирование файла внутри webview;
- классификация только «чувствительных» ключей — скрываются все непустые значения;
- облачная синхронизация, telemetry и удалённое хранение;
- принудительное переопределение явно выбранного редактора;
- запуск локального внешнего редактора из Remote SSH, WSL или Codespaces;
- поддержка произвольных форматов конфигурации кроме `.env` и `.env.*`.

## 4. Архитектура

```text
VS Code editor resolver
        ↓
CustomTextEditorProvider
        ↓
dotenv scanner → masked render model → static webview shell
        ↓
Reveal request → full render model → automatic hide
        ↓
built-in editor or user-configured external executable
```

Расширение остаётся источником истины для:

- текущей версии документа;
- состояния `revealed`/`hidden`;
- активного reveal-таймера;
- последней отправленной webview-ревизии.

Webview отвечает только за представление и отправку пользовательских действий.

### Основные компоненты

- `extension.ts` — активация и регистрация provider/commands.
- `config.ts` — типизированные настройки и безопасное чтение user-only конфигурации.
- `envParser.ts` — локальный scanner dotenv, возвращающий диапазоны значений и masked model.
- `envPreviewProvider.ts` — жизненный цикл панели, состояние, таймер и обновления документа.
- `messages.ts` — discriminated union протокола extension ↔ webview и runtime-проверка сообщений.
- `externalEditor.ts` — безопасный запуск внешнего редактора.
- `webview/main.ts` — DOM renderer и обработчики действий.
- `webview/styles.css` — тематизированный интерфейс без inline-скриптов и стилей.

## 5. Открытие файлов

В manifest регистрируется `CustomTextEditorProvider` с:

- `priority: "default"`;
- селекторами `**/.env` и `**/.env.*`;
- поддержкой суффиксов с несколькими компонентами, например `.env.production.local`.

Расширение активируется через `onCustomEditor` и `onLanguage:dotenv`. Второй activation event нужен только для обнаружения `.env`, открытого в обычном Text Editor из-за постоянного override.

Не используются:

- `onDidOpenTextDocument` для автоматической замены редактора;
- фиксированные задержки;
- последовательное закрытие text editors;
- изменение `workbench.editorAssociations` при установке или активации.

`priority: "default"` делает Env Veil редактором по умолчанию, но не запрещает VS Code использовать более приоритетную явную association. Если пользователь постоянно выбрал другой редактор, Env Veil не пытается молча перехватить файл: расширение показывает предупреждение и объясняет, как восстановить себя.

## 6. Разбор dotenv

Парсер не вычисляет значения, не разрешает переменные и не обращается к process environment.

Поддерживаются:

- `KEY=value`;
- пробелы вокруг `=`;
- необязательный префикс `export`;
- пустые значения без маски;
- одинарные, двойные и обратные кавычки;
- экранированные кавычки;
- многострочные значения в кавычках;
- многострочные значения с обратным продолжением `\` + перевод строки;
- комментарии и пустые строки;
- `LF` и `CRLF`;
- `#` внутри значения и `# comment` после значения;
- необычные имена ключей, если строка однозначно является присваиванием.

Правила безопасности:

- комментарии и пустые значения остаются видимыми;
- непустое значение заменяется фиксированной маской, не зависящей от длины;
- при многострочном значении сохраняются переводы строк для структуры, но не символы значения;
- строки, которые невозможно однозначно распознать как комментарий или присваивание, обрабатываются консервативно с точки зрения маскирования;
- исходный текст не преобразуется и не переформатируется.

Парсер возвращает:

- полный текст для reveal-состояния;
- отдельный masked text для скрытого состояния;
- диапазоны значений в обеих моделях;
- количество непустых значений;
- признак наличия multiline-значений.

## 7. Webview и безопасность

### Статическая HTML-оболочка

`webview.html` не принимает содержимое `.env` и не содержит даже masked document text. После загрузки webview отправляет `ready`, и только затем extension отправляет текущую модель.

### CSP и ресурсы

- `default-src 'none'`;
- `script-src ${webview.cspSource}`;
- `style-src ${webview.cspSource}`;
- `localResourceRoots` ограничены каталогом ресурсов расширения;
- `enableScripts: true`;
- `enableForms: false`;
- `enableCommandUris: false`;
- DOM создаётся через `createElement`, `createTextNode` и `textContent`, без `innerHTML` для пользовательских данных.

### Протокол

Сообщения типизированы и валидируются:

- `ready`;
- `reveal`;
- `hide`;
- `focusLost`;
- `openEditor`;
- `render`;
- `rendered`.

Render-сообщение содержит номер ревизии. Старые ревизии игнорируются, чтобы быстрые изменения документа и повторные reveal не оставляли webview в неправильном состоянии.

### Скрытое состояние

Чтобы уменьшить риск случайного копирования и появления устаревшего текста в видимом DOM, реализация не отправляет исходные значения в hidden-сообщении. После hide webview получает только masked model.

Это внутренний принцип реализации, а не пользовательская гарантия защиты от человека, который уже имеет доступ к VS Code и исходному файлу. Расширение также не сохраняет значения в webview state, logs или telemetry.

### Модель угроз

Расширение предотвращает случайный визуальный показ значений во время screen sharing, записи и демонстрации. Оно не защищает от локального кода, других расширений, DevTools или анализа уже снятого видео.

## 8. Reveal и автоматическое скрытие

Авторитетные состояния:

- `hidden` — начальное состояние каждой панели;
- `revealed` — значения видны до триггера скрытия.

Триггеры скрытия:

- кнопка `Hide Values`;
- истечение `envVeil.revealTimeoutSeconds`;
- `webviewPanel.onDidChangeViewState`, когда панель скрыта;
- `window.blur` в webview;
- `document.visibilitychange`;
- открытие файла во встроенном или внешнем редакторе;
- dispose панели.

После скрытия:

- отменяется текущий таймер;
- отправляется masked model;
- UI показывает `Values hidden`;
- повторное раскрытие всегда требует нового действия пользователя.

Webview не нуждается в `retainContextWhenHidden`. При восстановлении панель получает безопасное ready-соединение и рендерится скрытой.

## 9. Настройки

| Setting                          | Scope   | Default  | Назначение                                                                     |
| -------------------------------- | ------- | -------- | ------------------------------------------------------------------------------ |
| `envVeil.revealTimeoutSeconds`   | window  | `15`     | Время до автоматического скрытия, integer 1–3600.                              |
| `envVeil.openIn.mode`            | window  | `vscode` | `vscode` или `external`.                                                       |
| `envVeil.externalEditor.command` | machine | `""`     | Исполняемый файл, например `subl` или абсолютный путь.                         |
| `envVeil.externalEditor.args`    | machine | `[]`     | Аргументы до пути файла; `{file}` и `{workspaceFolder}` разрешаются extension. |

Команда и аргументы внешнего редактора читаются только из user/machine scope. Значения из workspace settings не используются для запуска процесса.

## 10. Открытие в выбранном редакторе

### Встроенный VS Code

Используется явное открытие default text editor с сохранением текущей editor column и unsaved document state.

### Внешний редактор

- запуск выполняется через аргумент-массив без `shell: true`;
- `{file}` и `{workspaceFolder}` подставляются как отдельные аргументы;
- если `{file}` отсутствует, путь файла добавляется последним аргументом;
- для Windows используется кроссплатформенный spawn wrapper;
- перед запуском значения в webview скрываются;
- если документ был изменён в другом редакторе и остался несохранённым, пользователь получает выбор: сохранить и открыть или отменить;
- ошибки показываются без содержимого файла;
- в remote context внешний режим отключается с объяснением и безопасным fallback на VS Code.

## 11. Интерфейс

Webview состоит из:

- компактного toolbar без перекрытия текста;
- primary action `Reveal Values` / `Hide Values`;
- secondary action `Open in Editor`; выбранный редактор показывается в подсказке и строке состояния;
- status text с количеством скрытых значений;
- видимого countdown во время reveal;
- scrollable preformatted content с сохранением переводов строк;
- empty state для файлов без значений.

Требования:

- поддержка light, dark и high-contrast themes через VS Code theme variables;
- адаптивная компоновка для узкого editor column;
- доступные labels, focus states и keyboard activation;
- `prefers-reduced-motion` не отключает безопасное скрытие;
- смена размера или webview recreation не оставляет значения видимыми;
- при обнаружении `.env` в другом editor показывается отдельное нативное предупреждение VS Code с инструкцией восстановления.

## 12. Команды

Минимальный набор:

- `Env Veil: Open Protected Preview`;
- `Env Veil: Reveal Values`;
- `Env Veil: Hide Values`;
- `Env Veil: Open in Configured Editor`.

Команды используют URI из активного text editor, активного custom editor или переданный command argument. Они не зависят от того, какой VS Code editor type сейчас активен.

## 14. Этапы реализации

   - manifest modern VS Code;

2. **Парсер**
   - scanner значений и диапазонов;
   - masked/full render models;
   - unit tests на обычных и malformed dotenv файлах.

3. **Custom editor**
   - регистрация provider;
   - static webview shell;
   - ready/revision protocol;
   - document updates и dispose.

4. **Reveal lifecycle**
   - global reveal/hide;
   - bounded timer;
   - focus loss;
   - configuration changes;
   - race tests.

5. **Открытие редактора**
   - встроенный VS Code;
   - external mode;
   - user-only settings;
   - обработка несохранённого документа перед запуском внешнего редактора.

6. **Интеграция и упаковка**
   - Extension Host tests;

   - проверка состава файлов пакета.

## 15. Тестирование

### Unit

- dotenv scanner;
- LF/CRLF и BOM;
- comments, `export`, empty values;
- escaped и multiline quotes;
- fixed-length mask;
- malformed input;
- state transitions;
- timer cleanup;
- stale render revision;
- message validation;
- argument resolution без shell.

### Integration

- открытие `.env` через VS Code editor resolver;
- поддержка `.env.production.local`;
- отсутствие тестового секретного значения в initial HTML и hidden render message;
- reveal показывает значения;
- timeout скрывает значения;
- tab/window focus loss скрывает значения;
- document edit во время reveal корректно обновляет модель;
- panel dispose отменяет timer и listeners;
- `Open in Editor` открывает выбранный встроенный или внешний редактор;
- после сохранения и возвращения preview обновляется и остаётся в hidden state;
- внешний редактор получает только путь и ожидаемые аргументы;
- встроенный VS Code сохраняет несохранённое состояние, а внешний режим предлагает сохранить несохранённый документ перед запуском;
- настройки workspace не могут подменить исполняемый файл;
- открытие `.env` в Text Editor вызывает предупреждение не чаще одного раза за окно;
- действие предупреждения открывает текущий файл в Env Veil, но не изменяет associations;
- инструкция восстановления в README соответствует фактическому VS Code UI.

## 16. Критерии готовности

- `.env` и `.env.*` открываются в Env Veil по умолчанию без задержек и гонок.
- Постоянный editor override отключает Env Veil, но пользователь получает видимое предупреждение и инструкцию по восстановлению.
- В скрытом состоянии видны только ключи, комментарии, структура и фиксированные маски.
- После hide в видимом DOM остаются только маски; значения исчезают из интерфейса до следующего Reveal.
- Reveal раскрывает все значения одновременно.
- Timer и focus loss всегда возвращают hidden state.
- Кнопка открывает выбранный пользователем редактор.
- Команда внешнего редактора не исполняется через shell и не берётся из настроек workspace.
- Unit, integration, lint, typecheck и clean package проходят.
- Runtime не выполняет сетевых запросов и не содержит telemetry.

## 17. Перед публикацией

Нужно отдельно определить:

- окончательное имя и package identifier;
- publisher;
- иконку;
- лицензию;
- описание и Marketplace copy;
- политику поддержки Remote environments, если она потребуется.

README обязательно содержит заметный раздел `Editor selection and protection`:

- после установки Env Veil работает без дополнительной настройки;
- `Reopen Editor With…` меняет только текущий файл;
- `Set Default` и `workbench.editorAssociations` создают постоянный override;
- при override Env Veil не маскирует значения;
- как вернуть Env Veil через `Reopen Editor With…` → `Set Default`;
- как исправить или удалить association в Settings JSON;
- переустановка расширения не удаляет association и не восстанавливает защиту.

Финальную доступность имени необходимо перепроверить непосредственно перед публикацией, поскольку Marketplace и GitHub постоянно обновляются.
