## 9. Проверить расширение

### Настройка внешнего редактора

Открыть user settings: `Ctrl+Shift+P` → **Preferences: Open User Settings (JSON)**.

```json
{
  "envVeil.openIn.mode": "external",
  "envVeil.externalEditor.command": "C:\\Program Files\\Sublime Text\\subl.exe",
  "envVeil.externalEditor.args": ["{file}"]
}
```

Правила, которые нельзя нарушать:

- `envVeil.externalEditor.command` и `envVeil.externalEditor.args` имеют **machine scope** — их записывают только в user settings. Значение в `.vscode/settings.json` молча игнорируется, это защита от подмены исполняемого файла проектом. `envVeil.openIn.mode` — window scope, его можно ставить где угодно.
- Аргументы задаются **массивом**. Строка `"--new-window {file}"` не разберётся на два аргумента.
- Процесс запускается без shell, поэтому `&&`, `|`, `;`, `>` не выполняются, а передаются как есть.
- Путь с пробелами берётся в кавычки JSON: `"C:\\Program Files\\Sublime Text\\subl.exe"` (в JSON обратный слэш удваивается).
- `subl` вместо полного пути работает, только если команда есть в `PATH` у того же пользователя, от имени которого запущен VS Code.
- `{file}` и `{workspaceFolder}` подставляются как отдельные аргументы; если `{file}` не указан, путь файла добавляется последним аргументом автоматически.
- `cwd` процесса — папка воркспейса, в которой лежит файл.
- Чтобы вернуть встроенный редактор, достаточно поставить `"envVeil.openIn.mode": "vscode"`.

Готовые примеры:

| Редактор     | `command`                                                                  | `args`                       |
| ------------ | -------------------------------------------------------------------------- | ---------------------------- |
| Sublime Text | `C:\\Program Files\\Sublime Text\\subl.exe`                                | `["{file}"]`                 |
| Notepad      | `C:\\Windows\\notepad.exe`                                                 | `[]`                         |
| VS Code      | `C:\\Users\\<user>\\AppData\\Local\\Programs\\Microsoft VS Code\\Code.exe` | `["--new-window", "{file}"]` |

### Ручная проверка

Запуск: F5 → `Run Extension (No Debug)`. Фикстуры лежат в корне проекта: `.env.manual-test`, `.env.manual-empty`.

1. **Маскирование** — в `.env.manual-test` видны `API_KEY=********` и `EMPTY_VALUE=********`; исходных значений нет.
2. **Reveal / Hide** — `Reveal Values` показывает значения и countdown, `Hide Values` возвращает маску. Значения прячутся также по таймауту, при переключении вкладки и при потере фокуса окна.
3. **Пустой файл** — `.env.manual-empty` показывает `EMPTY=********` без отдельной пустой панели.
4. **Встроенный режим** — `Open in Editor` при `envVeil.openIn.mode = "vscode"` открывает файл в обычном Text Editor; значения в Env Veil остаются скрытыми.
5. **Внешний режим** — при `envVeil.openIn.mode = "external"` (настройка из раздела выше) кнопка запускает настроенный редактор, а лейбл в шапке меняется на `External: <команда>` без перезагрузки окна.
6. **Отказ запуска** — временно указать несуществующую команду: появляется сообщение об ошибке и fallback во встроенный редактор, Extension Host не падает.
7. **Несохранённый документ** — воспроизводится только так, поскольку Env Veil не даёт редактировать:
   1. открыть `.env.manual-test` через `Reopen Editor With… → Text Editor`;
   2. дописать строку и не сохранять (во вкладке появится точка);
   3. вернуться через `Reopen Editor With… → Env Veil` — файл останется несохранённым;
   4. нажать `Open in Editor` → модальное окно `Save and Open` / `Cancel`; проверить оба варианта.
8. **Потеря защиты** — открыть `.env.manual-test` через `Reopen Editor With… → Text Editor`: появляется предупреждение, что Env Veil не активен и значения не маскируются, с инструкцией восстановления. Кнопка `Open in Env Veil` в предупреждении возвращает защищённый preview и **не** меняет `workbench.editorAssociations`. Повторного предупреждения в этом окне не будет.
9. **Нет ложных срабатываний** — файл `.env`, открытый сразу в Env Veil, предупреждения не вызывает; собственный `Open in Editor` предупреждения не вызывает; обычный файл вроде `env.js` — тоже.
10. **Изменение во внешнем редакторе** — настроить внешний режим, нажать `Open in Editor`, дописать строку в Sublime и сохранить. Вернувшись в Env Veil, увидеть актуальный файл: новая строка замаскирована, значения скрыты. Если в момент сохранения значения были раскрыты, Env Veil должен снова их скрыть.

### Проверка предупреждения о потере защиты

Фикстуры `.env.manual-test` и `.env.manual-empty` подходят под детектор, обычные файлы вроде `env.js` — нет.

Важно: предупреждение показывается **один раз за окно**. Чтобы повторить проверку, перезапускай Extension Development Host через F5.

1. Открыть проект в окне dev host и открыть `.env.manual-test` — он открывается в Env Veil, предупреждения нет.
2. `Reveal Values`, затем `Hide Values` — предупреждения нет.
3. `Ctrl+Shift+P` → `Reopen Editor With…` → **Text Editor**. Появляется короткое предупреждение: Env Veil не маскирует значения в этом файле, он открыт в другом редакторе. Внутри диалога инструкций быть не должно.
4. Нажать **Open in Env Veil** — файл возвращается в Env Veil, значения снова замаскированы.
5. Проверить, что настройки не изменились: `Ctrl+Shift+P` → **Preferences: Open User Settings (JSON)** — записи `envVeil.*` там быть не должно, а `workbench.editorAssociations` не должен содержать новой association.
6. Снова открыть файл через `Reopen Editor With… → Text Editor` — повторного предупреждения в этом окне нет.
7. Перезапустить dev host через F5, открыть `.env.manual-test` как обычно — он снова в Env Veil, предупреждения нет.
8. **Постоянная замена редактора:** `Reopen Editor With… → Text Editor`, затем `Reopen Editor With… → Set Default`. Закрыть вкладку и открыть `.env.manual-test` снова — он откроется сразу в Text Editor, и появится предупреждение. Дальше `Reopen Editor With… → Env Veil`, затем `Set Default`, чтобы вернуть защиту и убрать association.
9. Убедиться, что в консоли Extension Host нет необработанных ошибок.

Шаги 3–4 не должны оставлять значения на экране: Env Veil прячет их до открытия другого редактора, а в Text Editor файл показывается как есть — это ожидаемое поведение, именно о нём и предупреждает расширение.
