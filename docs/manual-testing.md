# Ручная проверка Env Veil

Проверка собранного расширения на обычном рабочем VS Code. Расширение ставится из VSIX, Extension Development Host и F5 не используются.

## Установка

Из корня проекта:

```text
code --install-extension dist/env-veil.vsix
```

Либо через интерфейс: Extensions view → **Views and More Actions…** → **Install from VSIX…** и указать `dist/env-veil.vsix`.

После установки: **Developer: Reload Window**.

Не запускай расширение из исходников одновременно с установленным — на одном файле будут мешать две копии.

## Фикстуры

В корне проекта лежат два безопасных файла без настоящих секретов:

- `.env.manual-test` — три непустых присваивания, включая одно пустое
- `.env.manual-empty` — одно пустое присваивание

Можно использовать свои файлы, но с фикстурами ничего случайно не утечёт.

## Настройка внешнего редактора

Нужна только для пунктов 5, 6 и 10. `Ctrl+Shift+P` → **Preferences: Open User Settings (JSON)**:

```json
{
  "envVeil.openIn.mode": "external",
  "envVeil.externalEditor.command": "C:\\Program Files\\Sublime Text\\subl.exe",
  "envVeil.externalEditor.args": ["--new-window", "{file}"]
}
```

Правила, которые нельзя нарушать:

- `envVeil.externalEditor.command` и `envVeil.externalEditor.args` имеют machine scope — их записывают только в user settings. Значение в `.vscode/settings.json` проекта молча игнорируется, это защита от подмены исполняемого файла проектом. `envVeil.openIn.mode` — window scope, его можно ставить где угодно.
- Аргументы задаются **массивом**. Строка `"--new-window {file}"` не разберётся на два аргумента.
- Процесс запускается без shell, поэтому `&&`, `|`, `;`, `>` не выполняются, а передаются как есть.
- Путь с пробелами берётся в кавычки JSON: `"C:\\Program Files\\Sublime Text\\subl.exe"` (в JSON обратный слэш удваивается).
- `subl` вместо полного пути работает, только если команда есть в `PATH` у того же пользователя, от имени которого запущен VS Code.
- `{file}` и `{workspaceFolder}` подставляются как отдельные аргументы; если `{file}` не указан, путь файла добавляется последним аргументом автоматически.
- `cwd` процесса — папка воркспейса, в которой лежит файл.
- Чтобы вернуть встроенный редактор, достаточно поставить `"envVeil.openIn.mode": "vscode"`.

Готовые примеры:

| Редактор     | `command`                                                                  | `args`                       |
| ------------ | -------------------------------------------------------------------------- | ---------------------------- |
| Sublime Text | `C:\\Program Files\\Sublime Text\\subl.exe`                                | `["--new-window", "{file}"]` |
| Notepad      | `C:\\Windows\\notepad.exe`                                                 | `[]`                         |
| VS Code      | `C:\\Users\\<user>\\AppData\\Local\\Programs\\Microsoft VS Code\\Code.exe` | `["--new-window", "{file}"]` |

## Чек-лист

1. **Маскирование** — открыть `.env.manual-test`: видны `API_KEY=********`, `DATABASE_URL=********`, `EMPTY_VALUE=********`. Исходных значений на экране нет.
2. **Reveal / Hide** — `Reveal Values` показывает значения и countdown в шапке, `Hide Values` возвращает маску. Значения также прячутся сами по таймауту, при переключении на другую вкладку и при потере фокуса окна.
3. **Пустой файл** — `.env.manual-empty` показывает `EMPTY=********` без отдельной пустой панели.
4. **Встроенный режим** — при `envVeil.openIn.mode = "vscode"` кнопка `Open in Editor` открывает файл в обычном Text Editor. Значения в Env Veil при этом остаются скрытыми.
5. **Внешний режим** — при `envVeil.openIn.mode = "external"` кнопка запускает настроенный редактор. Лейбл в шапке меняется на `External: <команда>` без перезагрузки окна.
6. **Отказ запуска** — временно указать несуществующую команду и нажать `Open in Editor`: появляется сообщение об ошибке, файл открывается во встроенном редакторе, VS Code не падает.
7. **Изменение во внешнем редакторе** — во внешнем режиме нажать `Open in Editor`, дописать строку во внешнем редакторе и сохранить. Вернувшись в Env Veil, увидеть актуальный файл: новая строка замаскирована, значения скрыты. Если в момент сохранения значения были раскрыты, Env Veil должен снова их скрыть.
8. **Несохранённый документ** — воспроизводится только так, поскольку Env Veil не даёт редактировать:
   1. открыть `.env.manual-test` через `Reopen Editor With… → Text Editor`;
   2. дописать строку и **не сохранять** — во вкладке появится точка;
   3. вернуться через `Reopen Editor With… → Env Veil` — файл останется несохранённым;
   4. нажать `Open in Editor` → модальное окно `Save and Open` / `Cancel`; проверить оба варианта: `Cancel` ничего не открывает и оставляет файл несохранённым, `Save and Open` сначала сохраняет.
9. **Потеря защиты** — открыть `.env.manual-test` через `Reopen Editor With… → Text Editor`: появляется короткое предупреждение, что Env Veil не маскирует значения в этом файле. Внутри диалога инструкций быть не должно. Кнопка `Open in Env Veil` возвращает защищённый preview и **не** меняет `workbench.editorAssociations`.
10. **Постоянная замена редактора** — `Reopen Editor With… → Text Editor`, затем `Reopen Editor With… → Set Default`. Закрыть вкладку и открыть `.env.manual-test` снова: он откроется сразу в Text Editor, и появится предупреждение. Вернуть защиту: `Reopen Editor With… → Env Veil`, затем `Set Default`, и убедиться, что association исчезла из настроек.
11. **Нет ложных срабатываний** — файл, открытый сразу в Env Veil, предупреждения не вызывает; собственный `Open in Editor` предупреждения не вызывает; обычный файл вроде `env.js` — тоже.
12. **Ошибки** — за время проверки не должно быть уведомлений об ошибках от Env Veil.

## Важно про предупреждение

Предупреждение показывается **один раз за окно VS Code**. Чтобы повторить проверку пункта 9 или 10, полностью перезапусти VS Code — предупреждение появится снова.

Предупреждение не должно появляться, когда файл открыт в Env Veil, и не должно появляться как следствие твоей собственной кнопки `Open in Editor`.

## Ожидаемое поведение, которое выглядит как ошибка

На пунктах 8–10 значения в Text Editor видны как есть. Это нормально: Env Veil маскирует файл только пока файл открыт в нём, и именно об этом предупреждает расширение. Проверять надо реакцию Env Veil, а не содержимое Text Editor.
